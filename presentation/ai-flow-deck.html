The One Principle

숫자는 SQL이 계산하고, AI는 해석만 한다

① 쌓기

판매·환불·조회를 불변 이벤트로 기록. 발생 시점 기준.

② 집계

정해진 시점에 SQL로 확정 숫자(dict)를 만든다. LLM은 개입 안 함.

③ 해석

그 숫자만 프롬프트에 넣어 AI가 서술·제안. 새 수치는 못 만든다.

모든 페르소나 프롬프트에 “숫자를 다시 계산하지 말고 해석만 하라”가 못박혀 있다 → 분석 비용↓, 환각 위험↓, 리포트는 재현 가능.

Data · Event Ledger

모든 것의 원천: commerce_events

상태값이 아니라 불변 이벤트 로그. 집계는 “지금 상태”가 아니라 발생 시점(occurred_at) 기준이라, 다음 달 환불이 이번 달 매출을 덮어쓰지 않는다.

멱등성 (중복 방지)

Langfuse · 개념

프롬프트를 코드 밖으로 꺼낸다

  • name — 페르소나 식별자 (예: customer-support-answer)
  • label = production — 지금 실제로 돌 버전을 가리키는 포인터
  • config — model·temperature·max_tokens·provider가 프롬프트에 저장 → 코드에 하드코딩 없음
  • fallback — Langfuse 불가 시 personas.py 로컬 프롬프트 + 기본 모델

모델 교체 = 재배포 없음

1
새 버전에서 config.model 변경
2
production 라벨을 새 버전으로 이동
3
캐시 TTL(기본 300초) 뒤 반영

안전장치: config의 gateway가 "openrouter"가 아니면 코드가 예외를 던져 엉뚱한 비밀값 사용을 막는다.

OpenRouter · 호출 상세

_generate_with_openrouter() 안에서

# Langfuse가 감싼 OpenAI SDK
from langfuse.openai import OpenAI
client = OpenAI(base_url=OPENROUTER_BASE_URL,
               api_key=OPENROUTER_API_KEY)

completion = client.chat.completions.create(
  model       = cfg["model"],
  temperature = cfg["temperature"],
  max_tokens  = cfg["max_tokens"],
  messages    = [{"role":"user",
                 "content": compiled.text}],
  extra_body  = {"provider":{
     "allow_fallbacks":True,
     "data_collection":"deny"}},
  langfuse_prompt = compiled.langfuse_prompt,
)

왜 이렇게?

  • allow_fallbacks — 1차 provider 장애 시 자동 대체
  • data_collection=deny — 학습 미사용 경로만
  • langfuse_prompt — 이 생성을 프롬프트 버전에 링크(재현)

fallback이 일어나면 실제 사용 모델(completion.model)이 요청 모델과 다를 수 있어, 그 값을 그대로 기록한다.

def _chunk_content(text, max=2000):
  while len(rest) > max:
    win = rest[:max]
    at = win.rfind("\n\n")   # 1순위: 문단
    if at < 0: at = win.rfind("\n") # 2순위: 줄
    if at < 0: at = max        # 3순위: 강제
    chunks.append(rest[:at])
    rest = rest[at:].lstrip()

DiscordNotifier.send()는 절대 예외를 던지지 않는다 — 알림 실패가 AI 파이프라인을 죽이면 안 되니까. 2000자 넘는 리포트는 문단 경계로 나눠 순차 전송.
