## 1. 피드백 ① 회원/비회원 구분 추천 — 반영 완료

발표 당일 저녁 AI 추천·코디 조합 엔진을 구현·배포했습니다. **로그인 여부(JWT 토큰 유무)에 따라
추천 근거 자체가 달라지는 3단계 개인화 로직**입니다.

| 단계 | 대상 | 추천 근거 |
|------|------|-----------|
| 1 | **전원** (로그인 무관) | **장바구니** — 지금 담은 상품과 어울리는 조합을 항상 최우선 |
| 2 | **회원만** | **조회 이력(최근 20개) + 구매 이력** — 실제로 조사해 추천 기준으로 사용. 비회원은 이 조회 자체가 코드에서 완전히 분기 처리되어 실행되지 않음 |
| 3 | 비회원·신규회원 폴백 | 위 근거가 하나도 없으면 **베스트셀러** 기반 |

- "비회원과 회원을 나눠, 회원은 실제 조회 상품 이력을 조사해 추천에 반영"이라는 요청을 **문자 그대로** 구현.
- 홈 화면 추천 섹션에 **회원/비회원 분기 문구**가 따로 표시됨.
- 관련 코드: `/recommendations`, `/recommendations/home` API · `AiRecommendationsStrip`(홈 스트립) · `AiRecommendationsPage`(전용 페이지 + 헤더 "AI 추천" 메뉴).

**추가로 같은 맥락에서 더 반영한 것 (2026-08-06):**
- **구매 이력 기반 사이즈 선호 개인화** — 카테고리별 최다 구매 사이즈를 찾아, 재고 있는 동일 사이즈 상품에 추천 가산점(+6.0), 응답에 `preferred_size_match` 노출. (별도 프로필 테이블 없이 `order_items.option_text` 파싱)
- **추천 엔진 캐시 테이블 전환** — 성능 개선.

## 2. 피드백 ② 카메라 가상 피팅 — Phase 0·1 구현 (웹캠 + 포즈 + 2D 착장)

발표 때는 카메라 기능이 전혀 없었지만, **웹캠 기반으로 1차 구현을 마쳤습니다.** 상품 상세 페이지의
**"📷 가상 피팅으로 입어보기"** 버튼으로 열립니다.

**지금 되는 것 (Phase 0·1):**
- **웹캠 실시간 포즈 추적** — `@mediapipe/tasks-vision`의 PoseLandmarker로 33개 신체 랜드마크를 프레임마다 추적(GPU→CPU 폴백).
- **어깨 기준 2D 착장** — 왼/오른쪽 어깨 좌표로 옷의 **각도·너비**를 계산해 상품 이미지를 몸에 겹침(셀피 반전). 크기·위치 슬라이더, 포즈 골격 토글, 사진 저장.
- **개인정보** — 영상은 브라우저 안에서만 처리, 서버 전송·저장 없음.
- **성능** — 무거운 모델이라 버튼 누를 때만 로드되는 별도 lazy 청크로 분리(`VirtualFitting.tsx`).

**아직 남은 것 (Phase 2~4 · 로드맵):** 인물 세그멘테이션, 앞/뒤 레이어링·다각도, 3D 메쉬 옷감 시뮬레이션, 상품별 투명 배경 착장 이미지 파이프라인. 이것들은 별도 컴퓨터비전/AR 작업이라 단계로 남겨뒀습니다.

> **⚠️ 솔직히 짚을 점:** 타입체크·빌드는 통과했지만 웹캠·포즈는 브라우저에서만 도는 영역이라 **실제 카메라 화면은 브라우저 실측이 한 번 필요**합니다. 또 데모라 상품 사진을 그대로 겹쳐서 아직 어색합니다 — 투명 배경 착장 이미지를 넣는 게 Phase 1 후속입니다. 단계별 전체 계획은 허브 HTML **"앞으로 할 일 → ★ 가상 피팅(웹캠)"** 섹션에 있습니다(`docs/codilab-project-hub.html`). 미팅에서 이 버튼을 실제로 눌러 보이면 좋습니다.

> 조회한 상품 기반으로 추천을 해달라는 거였고, 다른 하나는 카메라로 옷을 입어보는 가상 피팅이었습니다.
> 첫 번째는 발표 당일 저녁에 바로 만들어서 배포했고, 두 번째는 아직 못 했는데 왜 못 했는지랑 앞으로

**② 피드백①이 어떻게 반영됐는지 (1~2분) — 데모 곁들이면 최고**

> 최우선으로 보여주고요. 그 다음, **로그인한 회원이면 최근 조회한 상품 20개랑 구매 이력을 실제로
> 조사해서** 추천 기준으로 씁니다. 비회원은 이 조회 자체가 코드에서 아예 안 돌게 분기 처리했어요.
> 회원인데 이력이 아직 없으면 베스트셀러로 폴백하고요. 홈 화면에도 회원이냐 비회원이냐에 따라 안내

## 5. 예상 질문 & 답변

**Q. 추천이 진짜 개인화되는 건가요, 아니면 그냥 인기순인가요?**
> 로그인 회원은 실제 조회·구매 이력을 조사해서 근거로 씁니다. 이력이 없을 때만 베스트셀러로 떨어지고요.
> 장바구니가 있으면 그게 항상 1순위라, 담는 순간 추천이 바뀝니다.

**Q. 가상 피팅, 언제 할 수 있나요?**
> 1·2단계(웹캠 포즈 추적 + 어깨 기준 2D 착장)는 **이미 구현**해서 지금 눌러보실 수 있습니다. 옷이
> 자연스럽게 몸을 따라가는 수준(3~4단계: 세그멘테이션·3D 옷감)은 상품별 의류 에셋 파이프라인까지
> 필요해서 별도 스프린트로 이어서 진행할 예정입니다.

**Q. 왜 그걸 먼저 안 하고 검색·쿠폰부터 했나요?**
> 1인 개발이라 임팩트 대비 비용으로 우선순위를 정했습니다. 검색·리뷰·쿠폰·업로드는 기존
> FastAPI+React 구조를 그대로 늘리는 거라 빠르게 실서비스 완성도를 올릴 수 있었고, 가상 피팅은
> 완전히 새 서브시스템이라 뒤로 뺐습니다.

**Q. 모바일에서도 되나요?**
> 사이트 UI를 모바일 반응형으로 정리했습니다. 가상 피팅은 우선 컴퓨터 웹캠 기준으로 설계했고,
> 모바일 카메라는 이후 단계입니다.
