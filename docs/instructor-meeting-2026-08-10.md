## 1. 피드백 ① — 회원/비회원 추천 (반영 완료)

로그인 여부(JWT)에 따라 **추천 근거 자체가 달라지는 3단계 로직**.

| 단계 | 대상 | 근거 |
|------|------|------|
| 1 | 전원 | **장바구니** — 지금 담은 상품과 어울리는 조합을 항상 최우선 |
| 2 | **회원만** | **조회 이력(최근 20개) + 구매 이력**을 실제 조사. 비회원은 이 조회 자체가 코드에서 분기 차단 |
| 3 | 비회원·신규 | 근거 없으면 **베스트셀러** 폴백 |

- 홈 화면에 회원/비회원 분기 문구 표시. 전용 페이지(`/recommendations`) + 헤더 "AI 추천" 메뉴.
- 2026-08-06 추가: **구매 이력 기반 사이즈 선호**(카테고리별 최다 구매 사이즈에 추천 가산점), 추천 캐시 테이블.
- **미팅 포인트**: 장바구니에 담으면 추천이 즉시 바뀌는 걸 라이브로 보여주면 임팩트가 큽니다.

## 2. 피드백 ② — 카메라 가상 피팅 (Phase 0·1 구현 ✅)

발표 땐 카메라 기능이 전혀 없었지만, **웹캠 기반으로 1차 구현을 마쳤습니다.**

**동작 방식(질문 주셨던 것): 상품에 등록된 사진을 그대로 가져와 웹캠 위에 겹칩니다.**
별도 3D 모델이 아니라 카탈로그에 올라간 그 사진으로 "입어본 것처럼" 보여줍니다.

**지금 되는 것:**
- 상품 상세의 **"📷 가상 피팅으로 입어보기"** 버튼(어깨 기준이라 **상의·아우터**에만 노출).
- `@mediapipe/tasks-vision` **PoseLandmarker**로 33개 신체 랜드마크 실시간 추적(GPU→CPU 폴백).
- 어깨 두 점으로 옷의 **각도·너비** 계산 → 상품 이미지를 몸에 겹침(셀피 반전). 크기·위치 슬라이더, 포즈 골격 토글, 사진 저장.
- **개인정보**: 영상은 브라우저 안에서만 처리, 서버 전송·저장 없음.
- **성능**: 무거운 모델이라 버튼 누를 때만 로드되는 lazy 청크로 분리.

**남은 것(Phase 2~4 로드맵):** 배경 투명 착장 이미지, 인물 세그멘테이션, 앞뒤 레이어링, 하의/신발 부위별 배치, 3D 옷감 시뮬레이션.

> 상세 문서: `docs/virtual-fitting.md` (동작 파이프라인·라이브러리·조작·한계·튜닝값·로드맵·테스트법).
> 계획 로드맵은 허브(`docs/codilab-project-hub.html`) "앞으로 할 일 → ★ 가상 피팅"에도 있습니다.

## 3. 이번에 함께 완성한 것 (데모 자산 + 완성도)

**샘플 카탈로그 (라이브 데모용):**
- **SIGN 매장**으로 **모든 리프 카테고리 16개 × 상품 10개 = 총 160개 + 옵션 540개** 생성.
- **배포 DB(Neon)에 반영 완료 → 재배포 없이 지금 바로 배포 사이트에서 상품이 보입니다.**
- 이미지는 카테고리에 맞는 사진(셔츠→셔츠, 니트→니트, 스니커즈→운동화 등).

**품질·속도:**
- 상품 이미지 소스를 부정확·느린 것에서 **Unsplash CDN(빠르고 알맞음)**으로 교체 → 로딩 체감 개선 + 이미지 정확도.
- **이미지 파일 업로드(Vercel Blob)** 실제 업로드/공개 URL 동작을 라이브로 검증(판매자가 실제 상품컷 업로드 가능).

**UI/UX:**
- **모바일 반응형** — 데스크톱에서 사라지던 메뉴를 **햄버거 메뉴**로, 판매자 콘솔·체크아웃도 세로 스택.
- **로그인 화면** — 입력창·로그인·구글 버튼 폭을 맞추고 중앙 정렬.
- **카탈로그** — 서브카테고리 칩을 구분선 아래로 정리, 로딩 중 "불러오는 중…" 표시(기존엔 "상품 없음"이 잘못 떴음).
- **AI 추천 페이지** — 오른쪽 빈공간 제거(폭 채우는 그리드).

## 4. 라이브 데모 순서 (이대로 시연)

> **로컬에서 `pnpm dev`로 시연 권장** — 코드 변경분(가상 피팅·UI)이 아직 배포엔 반영 전이라(아래 6번 참고),
> 로컬이 가장 완전합니다. 상품·이미지는 배포에도 이미 라이브.

1. **카테고리 둘러보기** — 상의/하의/아우터/신발/악세사리 + 서브카테고리, SIGN 상품 160개.
2. **장바구니 담기 → AI 추천 변화**(피드백①) — 담는 순간 추천이 그 상품에 맞게 바뀜.
3. **로그인 → 회원 추천** — 조회/구매 이력 기반으로 근거가 달라짐(비회원은 베스트셀러).
4. **상의 상품 → 가상 피팅**(피드백②) — 웹캠 켜고 포즈 추적 + 옷 겹치기, 슬라이더로 맞추기.
5. **모바일 반응형** — 창을 줄이거나 폰으로 접속해 햄버거 메뉴 시연.

## 6. 솔직한 한계 · 배포 상태 (미리 알고 있기)

- **가상 피팅**: 타입체크·빌드는 통과했지만 웹캠·포즈는 브라우저에서만 도는 영역이라 **실제 화면은 브라우저에서 한 번 확인 필요**. 데모라 배경 있는 사진을 그대로 겹쳐 어색함(투명 배경 이미지가 다음 단계).
- **샘플 이미지**: 정확도 우선이라 카테고리당 대체로 1장이라 **반복**됨(가방만 3장). 주얼리/숏팬츠/카고는 근접 이미지. → 판매자 콘솔 **파일 업로드**로 실제 상품컷을 올리면 개선됨.
- **배포 반영 상태**:
  - **배포 사이트에 이미 라이브**(DB 데이터): SIGN 상품 160개, 알맞은 이미지.
  - **아직 배포 안 됨**(코드라 push+재배포 필요): 가상 피팅, 로그인/카탈로그/추천 UI 수정, 모바일 햄버거 등.
  - → `git push origin main` 후 Vercel 재배포하면 코드까지 라이브. **미팅 데모는 로컬(`pnpm dev`) 권장.**

## 7. 예상 Q&A

**Q. 추천이 진짜 개인화되나요?**
> 회원은 실제 조회·구매 이력을 근거로 씁니다. 이력이 없을 때만 베스트셀러로 떨어지고, 장바구니가 있으면 항상 1순위라 담는 순간 바뀝니다.

**Q. 가상 피팅은 어떻게 동작하나요? 3D인가요?**
> 지금은 상품에 등록된 2D 사진을 실시간 추적한 어깨 위에 겹치는 방식(2D)입니다. 3D 메쉬는 로드맵 Phase 4예요.

**Q. 가상 피팅, 언제 완성되나요?**
> 1·2단계(웹캠 포즈 + 2D 착장)는 이미 됩니다. 자연스러운 착장(세그멘테이션·3D)은 상품별 이미지 파이프라인까지 필요해서 별도 스프린트로 이어갑니다.

**Q. 상품이 실제 상품인가요?**
> 데모용 SIGN 샘플 160개입니다. 실제 판매용은 SIGN(또는 새 판매자)으로 로그인해 상품을 등록하면 됩니다.

**Q. 모바일에서도 되나요?**
> 반응형으로 정리했습니다(햄버거 메뉴 등). 가상 피팅은 우선 컴퓨터 웹캠 기준이고 모바일 카메라는 이후 단계입니다.
