문의 자동화에서 매출·수익을 설명하는 커머스 AI 비서로

AI Ops Studio는 쇼핑몰의 문의, 주문, 판매, 환불 이벤트를 모아 반복 업무를 자동화하고 운영자가 바로 행동할 수 있는 월별 경영 브리핑을 제공하는 B2B SaaS다. Demo Store는 실제 연동 전 제품 가치를 증명하는 데이터 원천이다.

React · TypeScript FastAPI · Python WebSocket LLM · RAG B2B SaaS Commerce Intelligence Discord Webhook Portfolio MVP
문서 통합 결정
AI는 판매·환불 이벤트마다 호출하지 않는다. 이벤트를 정확히 누적·집계한 뒤 정해진 시점에 집계 데이터만 AI에 전달해 분석 비용과 환각 위험을 낮춘다. 초기 알림 채널은 구현이 단순하고 데모가 명확한 Discord Webhook으로 고정한다.

제품 정의

무엇을 만들고, 무엇은 만들지 않는지 고정한다.

한 줄 정의

쇼핑몰의 고객지원과 운영 데이터를 자동 수집·집계하고, AI가 “무슨 일이 있었고 무엇을 해야 하는지” 설명하는 커머스 운영 비서형 B2B SaaS.

제품 목표

  • 배송·취소·환불 반복 문의를 자동 처리한다.
  • 판매·환불 이벤트를 누적해 매출과 환불률을 자동 집계한다.
  • 인기·부진·고환불 상품과 전월 대비 변화를 AI가 설명한다.
  • 광고비·원가·수수료를 반영한 추정 순이익을 계산한다.
  • 낮은 신뢰도와 위험 문의는 안전하게 상담원에게 이관한다.
  • 중요 운영 요약과 이상 징후를 Discord로 전달한다.

MVP 비목표

  • 실제 PG 정산과 세무·회계 확정 수치 제공
  • 모든 쇼핑몰 플랫폼 범용 연동
  • 전화·음성 상담 및 자체 LLM 학습
  • 완전한 노코드 워크플로 엔진
  • 판매·환불 이벤트마다 LLM을 호출하는 실시간 분석

데이터 획득과 연동 계약

고객에게 쇼핑몰 정보를 입력받지 않고 운영자가 최초 1회 연결한다.

운영자에게 요구

  1. 쇼핑몰 주소와 플랫폼 유형
  2. 상품·주문·배송 조회 권한
  3. 취소·환불 등 쓰기 권한의 별도 승인
  4. FAQ·배송·교환·환불 정책
  5. 상품 원가, 월별 광고비, 플랫폼·PG 수수료율
  6. 자동 답변과 상담원 이관 기준
  7. Discord 채널 Webhook URL과 알림 기준

구매 고객에게 요구

  1. 문의 내용
  2. 로그인 상태에서는 대상 주문 선택
  3. 비로그인 상태에서는 주문번호
  4. 이메일 또는 휴대전화 인증

비밀번호, 전체 카드번호, API Key, 주민등록번호는 요구하지 않는다.

09

AI 매출·수익 비서

숫자는 코드가 계산하고 AI는 변화와 우선순위를 설명한다.

Capture판매·환불 이벤트 저장
Aggregate일·월·상품별 집계
Compare전월·목표·상품 비교
ExplainAI 원인 후보와 제안
Deliver대시보드·Discord·HTML

코드가 결정하는 숫자

  • 총매출 = 결제 완료 주문 금액 합계
  • 실매출 = 총매출 − 취소액 − 환불액
  • 환불률 = 환불 완료 건수 ÷ 결제 완료 건수
  • 추정 순이익 = 실매출 − 원가 − 광고비 − PG/플랫폼 수수료
  • 상품 순위 = 판매 수량·매출·환불률별 정렬

AI가 설명하는 내용

  • 전월 대비 매출·순이익·광고비 변화 요약
  • 인기 상품과 가장 적게 팔린 상품 식별
  • 환불이 많은 상품과 주요 사유 후보
  • 비용 증가와 이익률 하락의 연관성 설명

정확성 원칙

LLM이 금액을 계산하지 않는다. 서버가 생성한 집계 JSON과 비교 결과를 프롬프트에 한 번에 전달한다. 비용 입력이 빠졌으면 “순이익 미확정”으로 표시하며, AI 문장은 관찰된 상관관계를 원인으로 단정하지 않는다.

Langfuse 페르소나 · MVP는 4개

입력 데이터, 출력 형식과 평가 기준이 다른 책임만 별도 prompt name으로 분리한다. 공통 말투와 안전 규칙은 호출 가능한 페르소나 수에 포함하지 않고 Prompt Composability로 재사용한다.

Prompt name페르소나책임출력상태
customer-support-answer고객지원 상담원주문·정책 근거로 문의 답변고객용 한국어 답변구현
support-triage문의 분류 담당유형·위험도·이관 여부 판단구조화된 분류 JSON예정
commerce-insight커머스 분석가코드가 계산한 지표의 변화·이상치 해석근거가 있는 운영 인사이트예정
commerce-monthly-report리포트 편집자월간 지표와 인사이트를 채널별로 편집대시보드·HTML·Discord 요약예정

공통 Sub-prompt 3개

  • _shared-brand-voice · 말투와 브랜드 보이스
  • _shared-safety-policy · 추측 금지, 개인정보, 이관 원칙
  • _shared-financial-truth · AI 계산 금지, 누락 비용 고지

개념 구분

  • name은 가져올 작업·페르소나의 식별자다.
  • label은 해당 name에서 실행할 버전 포인터다.
  • config는 모델과 생성 옵션을 버전과 함께 배포한다.
  • session_id는 여러 trace를 대화 단위로 묶으며 프롬프트 중첩 기능은 아니다.

Langfuse Config · 문의 답변 예시

{
  "gateway": "openrouter",
  "model": "~google/gemini-flash-latest",
  "temperature": 0.2,
  "max_tokens": 700,
  "provider": {
    "allow_fallbacks": true,
    "data_collection": "deny"
  }
}
배포 없는 모델 전환

새 prompt version의 config에서 모델을 바꾸고 검증한 뒤 production label을 옮긴다. 애플리케이션 재빌드는 필요 없지만 prompt cache TTL 기본값이 300초이므로 반영에는 최대 5분이 걸릴 수 있다. API Key와 Base URL 같은 비밀값은 Langfuse config가 아니라 서버 환경 변수에 둔다.

최소 권한

조회 권한과 취소·환불 쓰기 권한을 분리하고, 고위험 작업은 명시적 승인을 거친다.

실패 안전성

Timeout, 지수 백오프, 실패 큐, 멱등성 키, 감사 로그로 중복·유실·무한 재시도를 방지한다.

순이익은 운영자가 입력한 원가·광고비·수수료를 기반으로 한 운영용 추정치다. 세금, 인건비, 물류비 등 누락 비용을 표시하며 회계·세무 확정 자료로 제공하지 않는다.

MVP 출시 기준

고객지원과 경영 비서 가치가 함께 증명돼야 완료로 본다.

제품 완료 조건

  • 배송·취소·환불 대표 시나리오가 동작한다.
  • AI가 답변하거나 명확한 이유로 상담원에게 이관한다.
  • 처리 과정이 실시간 대시보드와 실행 로그에 반영된다.
  • 실패한 외부 작업을 확인하고 안전하게 재실행한다.
  • 판매·환불 이벤트로 전월 비교와 상품 순위를 계산한다.
  • 광고비·수수료 입력 시 추정 순이익을 재계산한다.
  • AI 월간 리포트와 Discord 요약이 같은 집계 수치를 사용한다.
  • Basic·Pro·Business 기능 접근이 서버에서 제한된다.

포트폴리오 완료 조건

  • 공개 데모와 역할별 테스트 계정이 있다.
  • 3분 내외 핵심 시나리오 영상이 있다.
  • 아키텍처와 기술 결정 기록이 있다.
  • 성능 개선 전후 수치와 테스트 결과가 있다.
  • API 장애·중복 Webhook 시연이 가능하다.
  • 월별 매출·환불·순이익 분석 데모를 1분 내 설명할 수 있다.
  • 요금제와 업셀 구조가 제품 화면에 드러난다.
최종 제품 메시지
